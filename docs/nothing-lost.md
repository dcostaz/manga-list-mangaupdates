# Nothing lost — MangaUpdates, 3.x wrapper → contract 4.0.0

`Plan-2026Q4-tracker-plugin-standardization.md` Phase 4.1. Every public method of the 3.x wrapper
(`api-wrapper-mangaupdates.cjs` at the tag `contract-3-final`) has exactly one row, classified **contract** (a §2
method the SDK's facade now generates, its source call in the client and its translation in the mapping),
**to client**, **to mapping**, or **deleted** (with the host call site that stops needing it; "no host caller" where
`D:\manga-list\cls` names none). `npm run check:nothing-lost` checks the table against the tag.

| Method | Classification | Where it went / why |
|---|---|---|
| `constructor` | deleted | The SDK builds the instance; nothing per plugin. The `require.main.require('axios')` fallback goes with it: the host injects `context.http`. |
| `init` | contract | `WrapperClass.init({ context, apiSettings, serviceSettings })`, generated by the SDK (contract §1.4). |
| `serviceName` | deleted | The SDK's `WrapperClass.pluginName` is the one name. Host fallbacks reading it (`coversearchorchestrator.cjs:869`) leave with Phase 5a's routing. |
| `pluginName` | contract | `WrapperClass.pluginName` and the descriptor's `pluginName`, from the manifest. |
| `pluginType` | deleted | The manifest's `pluginType` is the one source; the host reads the descriptor (`apipluginhandler.cjs:169`). |
| `capabilities` | deleted | The manifest's `capabilities` is the one source (the SDK refuses a mismatch at require time); the host reads the descriptor (`apipluginhandler.cjs:170`). |
| `credentialSchema` | deleted | A12: the manifest's `credentialOptions.fields` (`username`, `password`, the same keys, so stored credentials keep working). Host reads at `apipluginhandler.cjs:216`, `:3504`, `pluginservice.cjs:690` move to the descriptor in Phase 5a. |
| `contractVersion` | deleted | The manifest's `pluginContractVersion`, checked against the SDK at build and at load; no host caller. |
| `initialize` | contract | Generated; returns `{ status: 'ok' }`. |
| `getStatus` | contract | Generated; a Promise, no HTTP call (was synchronous). |
| `refreshCredentials` | deleted | Decision 4 / A5: a 401 is the SDK's one re-login and replay under the same credential. Host caller `plugincredentialbroker.cjs:225-230` goes in Phase 5a. |
| `search` | contract | Client `search` (`POST /series/search`, the per-scope search cache, `refresh`), mapping `search` (ranked on the 3.x title similarity, confidence 0–1, `pluginEntryId`, `canonicalUrl`, `cached`/`fetchedAt`). An exact match answers alone under `search.exactMatchPolicy: first`, as in 3.x. |
| `pullProgress` | contract | A1: one argument. Client reads the series' list membership (404 → all-null), the list it is on and the rating (`/series/{id}/rating`, a failed read leaves `rating` null as in 3.x); mapping gives `PluginPullResult` with the list's `type` as the token. |
| `pushProgress` | contract | Client posts chapter/volume (positive integers) to the series' current list and PUTs the rating (0 → DELETE, "cleared"); a series on no list is `not_found`; the lists it touched are re-read next time. Mapping reports `applied`. |
| `compareProgress` | deleted | A13: the host compares (its integer-chapter rule is the manifest's `progressAxes` `scale: integer`, A11); no host caller (analysis F13). |
| `subscribe` | contract | Client: the list `status` names — a list type token → the account's list of that type, or a numeric list id (the custom-list override, A2) → that list — then add (`POST /lists/series`) or move (`POST /lists/series/update`); mapping `{ listId, status: the list's type }`. The 3.x chapter/volume/rating in a subscribe left the contract. |
| `getCredentials` | deleted | No credential is held (A5); no host caller. |
| `setCredentials` | deleted | A5: the credential arrives in each call's `callContext`. Host hydration sites (`apipluginhandler.cjs:2206`, `:2791`, `:2957`, `:3669`, `:3707`, `plugincapabilitydelegate.cjs:87`) go in Phase 5a/5b. |
| `getToken` | to client | The client's `auth` strategy: `exchange` is the `PUT /account/login` session login (12 h, retired a minute early), `apply` the Bearer header; the SDK keeps the token in memory per identity, never in the host cache. No host caller. |
| `testCredentials` | contract | A9; the SDK runs the client's login exchange on an identity of its own: `true`, or `false` for a refused login (a transport failure throws, where 3.x answered `false`). |
| `refresh` | deleted | The 3.x global cache-bypass toggle; the per-call `options.refresh` (search) and per-scope cache keys replace it. No host caller. |
| `getSeriesUrl` | to mapping | A10: `canonicalUrl` on candidates and detail, from the series' own `url`. Host caller `trackersearchdelegate.cjs:644-646` stops needing it in Phase 5a. |
| `getUserLists` | to client | The client's `lists()` (`GET /lists`), the list-of-lists cached per scope. No host caller. |
| `getSeriesListStatus` | to client | The client's `membership()` (`GET /lists/series/{id}`, 404 → none), always asked fresh. No host caller. |
| `getReadingStatusFromListId` | deleted | F18 and Decision 2: the token is the list's own `type`, never a list's position matched against `statusMapping`; the custom-list override is the host's (A2). No host caller. |
| `getListSeries` | to client | The client's `listSeries()` (`POST /lists/{id}/search`, paged by `total_hits`), cached per scope until a write to that list clears it (2026-11-07). No host caller. |
| `getReadingList` | contract | Client reads every list, the custom ones too, each whole; mapping keeps the list's `type` as the token and its id as `listId` (A2, A6). No `hostProgressByEntryId`, no `comparison` (A13). |
| `getUserProgress` | to client | The client's `pullProgress` source call. No host caller. |
| `getSerieDetail` | to client | The client's `series()` (`GET /series/{id}`), cached per scope (`cache.ttl.seriesMetadata`). No host caller. |
| `getSeriesById` | to mapping | `_normalizeSeriesData` is the mapping's `contribution()` (lookup, enrich). No host caller. |
| `queryLive` | contract | Client asks the series fresh (404 → the `not_found` arm), mapping the `ok` arm without `linkState` (A4). |
| `summarizeEntries` | contract | Decision 3 / A4: the series' volatile state (status text, its state word, latest chapter, last update) from each series, per entry; no longer answered from the user's whole reading list, no `linkState`. |
| `buildLinkContribution` | deleted | A8: the link path is `search.query` → the Reference → `enrich`. Host callers `apipluginhandler.cjs:2203-2210`, `plugincapabilitydelegate.cjs:83-94` go in Phase 5a. |
| `syncEnrichment` | deleted | No host caller (analysis F13). |

| `serieSearch` | to client | The client's `searchRows()` (`POST /series/search`, the title types, the per-scope cache with its fetch time). No host caller. |
| `getSeriesCover` | deleted | `searchCovers`/`downloadCover` read the cover from the series; no host caller. |
| `updateSeries` | deleted | Editing MangaUpdates' series record is no contract offer; no host caller. |
| `updateSeriesCover` | deleted | Uploading a cover to MangaUpdates is no contract offer; no host caller. Its `api.endpoints.seriesImage.*` settings go with it. |
| `deleteSeriesCover` | deleted | As `updateSeriesCover`; no host caller. |
| `removeSeriesFromList` | to client | The client's `unsubscribe` source call: the series id posted to `/lists/series/delete` (live-confirmed 2026-11-07), an `exception` reply in any case a refusal. No host caller. |
| `unsubscribe` | contract | Client: on no list (or an id naming no series) is success with no call (idempotent, §2); else the site's removal; the list it left is re-read next time. |
| `updateListSeries` | to client | The client's `pushProgress`/`subscribe` `POST /lists/series/update` (chapter and volume as positive integers). No host caller. |
